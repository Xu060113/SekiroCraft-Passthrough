# MC 忍杀动作与只狼接口方案

本方案对应“做一个 MC 忍杀动作，再适配接口”：MC 渲染史蒂夫的动作，只狼执行敌人的阶段与死亡事件。它是后续实现方案；本次过场修复没有上线 MC 忍杀动画或替换现有 Boss 自动扣红点模式。

触发方式按最新要求改为“出现原生红花后自动忍杀”，不再绑定 R。原生资格、目标、距离和朝向均确认后，MC 对本次候选令牌自动请求一次；相同红花的连续帧不能重复启动，目标/阶段改变需使用新令牌。剧情接管、背包/原生菜单、死亡和断线时不自动请求。当前仅移除了 R 转发，红花检测与自动忍杀仍属于后续接口实现。

## 动作怎样接入

沿用仓库已有的 Fabric 1.20.1 模组，不另开一个不兼容的游戏版本。MC 客户端播放专用动作，原生 DLL 通过共享内存回应动作请求；MC 玩家和敌人代理的碰撞、装备与实体身份继续沿用当前桥接。

先做可独立预览的动作：靠近目标、身体转向、持刀手蓄力、刺入、拔刀、回到正常姿势。第三人称表现为史蒂夫身体和四肢的关键帧；第一人称表现为手臂和武器动作。渲染时修改模型姿势，避免把视觉靠近直接写成真实瞬移或穿过墙。目标站位必须由原生端确认后再允许真实位移。

关键帧采用单一时间轴，并设置一个 `strike` 命中标记。动画时长只用于画面表现；阶段结算、是否能移动、是否已经击杀以原生回执为准。不能仅凭“播放了 1 秒”判断 Boss 已死亡。

## 接口约定

新增独立的 Deathblow 通道并升级配对协议版本；不能把旧 `NativeActionRequest.kind=1` 的普通攻击请求重解释成带目标的忍杀。结构尺寸、版本和双方能力位必须一致。

| 消息 | 方向 | 必须携带的信息与含义 |
| --- | --- | --- |
| `Candidate` | 只狼 → MC | 会话、玩家生命身份、目标 ID、目标阶段、距离、朝向、可忍杀类型、有效期；由原生端确认资格 |
| `Request` | MC → 只狼 | 请求序号、候选令牌、目标 ID 和阶段；确认红花后，对同一令牌自动触发一次 |
| `Accepted` / `Rejected` | 只狼 → MC | 是否接收、拒绝原因、动作类型、站位；只有接收后才播放正式动作 |
| `Strike` | MC → 只狼 | 原请求序号与候选令牌；到达命中关键帧，允许提交结算一次 |
| `Settled` | 只狼 → MC | 原生实际确认的阶段前后值、目标状态、是否最后阶段；不能用 MC 动画结束伪造确认 |
| `Cancelled` | 双向 | 死亡、读档、断线、目标失效或剧情接管，释放动作控制 |

只狼端按当前实例重新验证距离、阵营、阶段和资格，拒绝陈旧、跨生命、重复或已经消失的目标。序号与令牌保证重发不会再扣一颗红点；客户端传来的指针、动画编号或任意地址都不作为可调用入口。

流程为 `Idle → Candidate → Requested → Accepted/Playing → Strike/WaitingSettlement → Settled → Recover → Idle`。拒绝与取消回到普通操作；超时释放控制并记录原因，不通过手动扣红点补成“成功”。恢复状态不能沿用原先忍杀的固定等待，否则仍会出现动作后四五秒不能移动。

## 原生端还缺什么

已有接口能提供附近目标身份、HP、姿态和 Boss 阶段，也能提交普通攻击。当前没有经过验证的通用“目标可忍杀”读取及“完成一次原生忍杀”调用。采集到的攻击类型 5 参数也不能直接当作所有 Boss 通用的最终忍杀入口。

需要查明原生的资格检查、配对攻击状态、阶段推进及最后击杀事件。普通人形、赤鬼等小 Boss、多个阶段的大 Boss、特殊剧情收尾分别验证。HP/姿态到达阈值可以作为候选搜索条件，不能单独证明原生忍杀资格。最后阶段必须确认原生死亡与事件结果，不能仅检查 `bossNode` 减一。

这说明 MC 动画可以独立实现，完整替代自动扣红点仍依赖原生接口。只做动画再写红点数，仍是现有简化方案，无法解决剧情门槛、奖励与存档问题。

## 实施顺序与验收

1. 制作 MC 动作预览和时间轴：第一/第三人称一致，拔刀后姿势恢复，取消时不残留模型变形；预览不扣敌人 HP 或阶段。
2. 增加有版本约束的双端消息与状态机：测重复请求、重复命中、旧阶段、换角色、断线、死亡和过场中断；默认仅预览，结算入口未验证时不公布完整忍杀能力。
3. 验证原生资格与结算入口：先普通敌人，再赤鬼两个阶段，再大 Boss 的阶段与最终事件；原生狼仍保持隐藏，MC 动作与原生敌人状态衔接。
4. 经游戏测试后，用新模式替换自动扣红点；旧模式作为显式兼容选项。未验证的特殊 Boss 不强行调用，显示不可用原因。

每次 GitHub 提交与推送均须先经过你的游戏测试，并得到上传授权。动作原型、接口离线检查和完整实机忍杀是三个不同的验收结果，记录时分别说明。
