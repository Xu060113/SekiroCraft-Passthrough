# 攻击特效、Boss 难度和原版防御验收

补丁 `gameplay5-defense-render`，协议 v3。DLL、JNI 和 JAR 必须成对安装。本轮离线检查不启动两款游戏。

## 改动

- 只狼场景就绪检测不依赖 MC 第一帧。启动、重新连接或调整分辨率后，可先由已执行的原生场景绘制启动桥接；画面合成仍只接受与相机匹配的 MC 帧。
- 仅可写深度的不透明场景绘制参与场景深度/相机选择。混合粒子、攻击拖尾和无法配对的相机不能挤掉已确认的场景。F7 显示忽略特效绘制计数。
- 普通敌人默认一条血量对应 40 点 MC 伤害，Boss 每阶段为 200 点；姿态伤害使用相同比例。保留原生阶段流程，绝不为了调难度修改最大 HP 或加红点。
- 已核对的原生攻击 HP setter 路径先排队，再由真实 MC `ServerPlayerEntity.damage` 处理。健康报告回传实际扣血，避免护甲减伤两次、伤害重复和先死亡再补血。
- 盾牌按原版起手、方向与持续使用规则处理；装备耐久、护甲/韧性、保护附魔、抗性、吸收血和受伤冷却由 MC 负责。
- 远程来源先取包内或原生调用传入的有效角色；无角色引用时，用已核对的碰撞包 `+150`（攻击中心指向命中点的单位方向）还原来袭侧。无效、零、垂直或不相关命中数据不生成格挡方向。指纹核对的共用攻击扣血路径支持远程调用，仍要求同线程、当前玩家的近期命中。
- 未确认来源的攻击不授予全方向盾牌免疫。失联、过期确认、满队列、原生忍杀、环境/脚本伤害及桥接自己的写血绕过排队，保留原生伤害。

## 定向实机步骤

先进入两款游戏的存档，再执行 `/sekirobridge on` 并切回只狼。确认首次开启出现 MC 人物、方块和 HUD；关闭再开启桥接、调整只狼分辨率后重复，确保没有互相等待第一帧。随后进行以下防御和战斗检查。

1. 非和平生存模式，暂不带护甲盾牌，让同一原生敌人攻击一次，记录血条变化。
2. 穿完整钻石装备重复同类型攻击，检查扣血更少、装备耐久下降；比较有/无保护附魔。不要用创造模式测试减伤。
3. 副手装备盾牌，面向攻击者并按住右键至少 5 tick；验证挡住正面攻击、盾牌音效和耐久。背向同一攻击者应受伤，松开右键应受伤。
4. 多次攻击普通敌人和一名 Boss，记录单次武器伤害和每阶段击杀次数；7 点伤害默认约扣 Boss 一阶段 3.5%，暴击另计。
5. 在第一/第三人称，用同一种只狼刀光/火焰攻击经过 MC 方块和人物，确认不再整帧消失。检查 F7 的 `Ignored FX draws` 与 `native hits routed to MC` 计数。
6. 验证死亡/复活、背包点击、F6 原生菜单与 M 钩索没有回归。切换创造、生存以及关闭桥接后，确认免伤位恢复。
7. 生存模式对同一弓箭/火枪敌人：面向来袭方向举盾至少 5 tick，比较举盾、松开盾牌、背向来袭三种情况。F7 的 `Defense direction / trajectory / unknown / core path` 和日志同名计数用于判断远程来源是否传到 MC。炮弹、范围攻击、法术需另测，不能由普通弹丸测试推断全部攻击已适配。

## 已知边界

不透明且写深度的特殊特效仍可能被当成场景，需针对实际渲染路径继续核对。原生坠落/脚本死亡的装备减伤未接入。原生击退、姿态消耗与狼的受击动画没有变为 MC 盾牌动画。Boss 脚本与最终奖励仍需单独验收。本轮不把离线夹具当成上述实机验收已经完成。
