# 大体型 Boss 受击框回归

## 动画部位判定更新

2026-10-09 用户确认本轮游戏测试完成并授权发布；下方检查单保留用于不同 Boss、部位和武器的回归，不代表所有特殊模型已覆盖。

中央移动胶囊不足以覆盖怨恨之鬼、狮子猿等模型伸出的四肢；特殊角色也可能没有可用胶囊尺寸。本次新增读取当前主 FLVER 模型每根骨骼的网格包围盒，用当前骨骼 3×4 矩阵和角色世界矩阵转换成多个受击区域。算法不按 Boss 名称或血量猜体型：有有效模型数据的角色自动使用其自身各部位。

同一个 Boss 仍只有一个 MC 实体、一个阶段 ID 和一份血量。实体整体外框用于发现候选，射线、范围相交、距离和实际伤害点使用各个部位；`expand/offset/stretch` 后仍保留部位之间的空隙。另补充跨实体分区的查询，避免长手臂远离脚下所在分区时找不到目标。原生距离和伤害位置校验按当前模型部位计算，替代“距根节点 64m 内、伤害点距根节点 12m 内”的大型模型漏判；范围仍限制为玩家距任一部位 64m 内，命中点距部位 2m 内。

新独立通道 `actor-parts-v1`，能力位 8192。读取核对 1.06 代码指纹、模型虚表、主资源、骨骼数量、数组指针以及两次姿态副本；不跨地图缓存原生指针。最多 1024 根骨骼、128 个部位；超出预算时合并相邻骨骼区域以保留全部覆盖，并在日志标记 `source=2`，不会截掉最后的手指或尾部。无几何骨骼忽略；有几何骨骼的数据异常会拒绝整个快照。服务端仅接受同实体、阶段和场景且 250ms 内的部位，失效时回退到已验证胶囊。

**范围与验收边界：**这是随动画变化的骨骼包围盒，并非逐三角形碰撞。细小轮廓和同一个骨骼盒内部的空隙仍有近似，合并模式会增加空隙覆盖。主模型只有骨架、身体来自独立装配模型时仍回退胶囊，装配网格和独立剧情部件尚未完整接入。樱龙、巨蛇等特殊战斗的 NoDamage/剧情条件仍由只狼决定，不能将“命中几何”误称为所有阶段均可伤害/击杀。不能宣称每个 Boss 已完整通过游戏测试；不同第三方武器重新创建普通 Box 或采用专有碰撞算法时也可能需要单独兼容。

只读运行诊断已验证当前加载巨蛇的 140 根骨骼、122 个有效主模型区域及世界坐标；并验证鲤鱼的 53 根骨骼、29 个区域。没有修改游戏内存或启动游戏。核心离线回归包括动画旋转组合、远离根节点的肢体、区域间空隙、旧姿态/地图拒绝、超预算保留尾部、跨进程 JNI 输送及 MC 实际 Box 射线/距离/范围计算。

验收优先测试怨恨之鬼、狮子猿、赤鬼，再对人形 Boss 和普通士兵做对照：分别用近战、箭、枪械、拔刀剑攻击头、胸、背、左右臂和腿；测试挥臂、转身、移动时的对齐；攻击四肢间的空气应无伤害，一次范围攻击不应因为多个部位重复扣血。记录具体 Boss、部位和武器。日志 `Actor model parts ... bones=... parts=... source=1` 表示主模型骨骼判定已启用，`source=2` 为合并模式；只有 `Actor hitbox ...` 而无部位记录时不能认定全模型覆盖。F3+B 的原版框仅显示用于查询的总体外框。

两个游戏正常退出后再安装成对 DLL/JAR。当前构建与验收状态见本地 `build/verification.json`；用户实机测试确认后才可提交 GitHub。

## 上一版胶囊判定（保留为回退）

原生敌人代理以前全部固定为宽 0.6、高 1.8，导致大体型敌人的胸口、侧面等位置在画面上被攻击命中，却没有进入 MC 受击框。本次改为读取该实体当前的只狼角色胶囊高度/半径，转换为 MC 的整体受击 AABB；有效的模型垂直偏移和桥接缩放一起应用。客户端通过一个原子的 DataTracker 向量收到与服务端相同的宽、高、偏移，供原版准星、近战、箭、TaCZ 的实体射线和拔刀剑的区域查询使用。

取消原生代理额外的三 tick 移动插值，减少实体受击框落后于只狼画面的情况。插在敌人身上的箭也按新尺寸分布。只狼原生模型和 Boss 血量设置没有修改。

这仍是整体胶囊对应的 AABB，**不是随骨骼动画变化的逐部位原生受击球**。伸出的手臂、剑、空隙及特殊剧情 Boss 的独立部位不保证与轮廓完全重合；不能把剑气本身的尺寸问题当作 Boss 整体尺寸问题已经解决。不同第三方武器的查询规则仍需游戏验证。

## 数据来源与隔离

- 当前 1.06 exe 指纹检查之外，另外验证 `BBEF20/BBEF30` 的字段 getter、`BC82A2` 的存储以及 `BC2E5F/BC2E76` 的 NpcParam 读取指令。已缓存的 1.06 映像离线反汇编关联到 `SprjChrPhysicsModule` 的当前角色胶囊 `+DC/+E0`。读取同时核对模块虚表 `+2A89040` 和 owner。
- NPC ID 参考 [ElaDiDu 只狼练习表](https://github.com/ElaDiDu/Sekiro-Practice-CT)，参数仓库布局交叉核对 [Smithbox 1.06 配置](https://github.com/vawser/Smithbox/blob/main/Smithbox.Release/Output/Assets/PARAM/SDT/Param%20Reloader/1_6_0_0.json)，`chrHitHeight/chrHitRadius/hitYOffset` 定义参考 [Paramdex NpcParam](https://github.com/soulsmods/Paramdex/blob/master/SDT/Defs/NpcParam.xml)。不复制游戏资源或修改 Param。
- 独立 `actor-shapes-v1` 通道；保留帧/control/战斗 ABI v3。能力位 4096 表示新宿主提供体型，旧宿主不触发该读取。体型必须匹配实体 ID、Boss 阶段与场景 epoch，并在 250ms 内；不传输原生指针。
- 非法尺寸、外来 owner、未知模块、无法读取的字段使用人形回退；模型偏移读失败只回退偏移，不丢弃有效宽高。日志 `Actor hitbox ... native=1 width=... height=... offset=...` 可确认实际数据，`native=0` 表示仍在回退。

## 用户测试

1. 正常关闭两个游戏，使用构建后的成对 DLL/JAR 更新包。保持当前 Loader、API 和武器模组；不要只替换一端。
2. 开启桥接，在赤鬼、狮子猿或怨恨之鬼等大型敌人身前，分别攻击脚部、胸口和左右身体边缘。再对普通士兵做对照，确认没有把普通敌人统一放大。
3. 使用近战、弓箭、枪械与拔刀剑剑气分别测试：射线/范围进入躯干应产生伤害；从身体外侧掠过应保持未命中。截图或记录具体武器、敌人、站位，便于区分武器自己的范围限制。
4. 用 F3+B 临时显示 MC 受击框，观察站立、移动、转向和 Boss 阶段切换时的对齐。完成后关闭调试框。
5. 按 F8 关闭/重开桥接，或切换地图，确认旧 Boss 受击框不残留；测试普通敌人、背包和盾牌没有退化。

离线验证包括生产读取器的 owner/虚表/参数校验、实际 MC Box 的射线与范围相交、实体阶段/epoch/时间隔离，以及 C++→共享内存→JNI→Java 的尺寸运输。离线通过不等同于已完成上述游戏验收；用户确认测试后才可提交 GitHub。
