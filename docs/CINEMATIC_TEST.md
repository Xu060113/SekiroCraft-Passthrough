# 过场画面恢复测试

本地补丁增加只狼 1.06 原生 `SprjRemoMan` 过场生命周期的只读检测。检测代码受可执行文件指纹、getter 指令和对象虚表约束；不会跳过或修改剧情动画。MC 与只狼必须一起更新。

进入过场后，暂停 MC 画面合成、输入转发、相机覆盖、移动约束和攻击提交，恢复原生人物的可见性。保持桥接会话，MC 跟随原生脚本位置；结束后只接收恢复时生成的新画面和人物状态，避免旧 HUD、旧镜头或旧位置再次出现。普通攻击和钩索动画不按剧情过场处理。

离线检查覆盖状态内存失效、错误虚表、普通待机、过场开始/结束、已完成的 Finish 状态、短时读失败、卸载和恢复帧边界；这些检查不能证明每一种实机剧情均可检测。Finish 清除活动位并将下一状态设为 -1 后即可恢复，不能一直把最后一个状态当作正在播放。

静态核对使用支持版本的本地载入镜像：`base+0x3d8dc08 → SprjRemoImp → +0x08 SprjRemoMan`。构造函数 `0xed1520` 保存该管理器，`0xed3400` 创建运行时 owner；虚表 `0x2b41520` 与 `0x2b3f9a8` 的 RTTI 分别对应这两个类型。状态 getter `0xec6e50` 读 `+0x40`；注册表 `0x3d8d6e0` 将 Prologue 至 Finish 对应到状态 2 至 8。与 `SprjRemoIns` 或 `DLRuntimeClassImpl` 类型元数据混用会导致检测无效，检查时需核对实际对象类型。

请测试以下场景：

1. 开启桥接后，触发一段能够播放或跳过的剧情过场；物品栏、准星、MC 人物、方块和背包均不应叠在剧情上。只狼原生字幕和跳过提示保持正常。
2. 分别完整播放和跳过过场；结束后应恢复 MC 操作，不能卡住镜头、回到旧位置或要求重新输入桥接命令。
3. 保留 MC 背包打开状态再进入过场；跳过动画时的点击不能回放成背包取物或放置方块，结束后重新点击可正常操作。
4. 按 M 使用钩索，普通跳跃、攻击：这些动作仍显示 MC 画面，不能误判为剧情过场。
5. Boss 转阶段动画与结局动画分别测试；报告 Boss/剧情名称以及问题发生在进入、播放还是结束时。

如果仍有覆盖，查看 `passthrough.log` 中 `cinematic`、`remoValid`、`remoStep`、`remoNext`，可区分检测失败与恢复失败。此修复纳入 2026-10-08 用户授权发布的更新，各种剧情场景仍需分别验证。忍杀动画的后续方案见 [MC 忍杀接口设计](MC_DEATHBLOW_DESIGN.md)。
