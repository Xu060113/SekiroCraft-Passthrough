# 拔刀剑剑气融合显示修复

针对本机 SlashBlade: Refabricated `1.20.1-1.4.0-Resharped-1.9.65` 的发光剑气、挥刀光效和蓄力层。实际 JAR 中 `DriveRenderer` 使用 `renderOverridedLuminous`，该层使用 `COLOR_MASK`：RGB 已绘制，但不写深度。桥接合成要求 MC 像素带有效深度，因此在透明背景上的这类剑气被丢弃。`JudgementCutRenderer` 使用另一条减法混合路径，不在本次加法发光修复范围内。

桥接开启时，仅在已核对的拔刀剑加法混合层绘制期间启用深度写入。处理在 `ShaderProgram.bind` 之后执行，避免着色器 JSON 再次覆盖混合状态；绘制结束或抛出异常时恢复原始 GL 状态。RGB 保留加法发光，alpha 保留底下 MC 人物/方块的覆盖率。只狼合成接受带深度的零 alpha 发光 RGB，同时继续检查原生地形遮挡。桥接关闭时保持独立 MC 的原行为，未安装拔刀剑时不需要额外依赖。

离线回归使用隐藏 OpenGL 窗口实际绘制剑气，经过生产 FBO 拷贝，再将 RGB/深度交给生产 D3D11 合成器，检查正面可见、墙后遮挡、透明 texel 不写深度、发光不抹去原有人物覆盖率，以及异常后的状态恢复。另核对本机拔刀剑 JAR 的渲染层名称和实际调用。不会启动游戏。

实机验收：

1. 两端进入游戏并开启桥接，面向空地释放剑气，比较 MC 与只狼中的显示；测试第一人称及 F5 第三人称。
2. 分别使用普通挥刀光效、远程剑气和蓄力，检查是否可见、有无黑色矩形、残影或 MC 人物闪烁。若次元斩仍缺失，请单独记录，不能用本次加法发光检查替代其验收。
3. 面向墙体释放剑气并侧移镜头，墙前部分应可见，墙后部分应被只狼地形遮挡；MC 方块也应遮挡后方剑气。
4. 关闭桥接后在 MC 中重复动作，特效应保持原状；重新开启、读档和播放过场后再检查。
5. 同时验证上一次大体型 Boss 受击框修复：躯干、侧面及移动时的剑气/近战命中是否对应可见模型。

限制：本次针对已核对的加法发光层；不保证其他模组的自定义着色器、减法特效或任意拔刀剑版本。现有单层世界颜色/深度传输无法分别处理同一像素里多个不同深度的半透明表面，复杂叠加仍需实机检查。完整发布仍须先经过用户游戏测试与 GitHub 上传授权。
