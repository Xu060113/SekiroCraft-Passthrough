# 界面、原生动作与 Boss 阶段定向验收

补丁 gameplay4-gui-native-combat 使用协议 v2，必须配套更新只狼 DLL 和 MC JAR/JNI。离线测试不能证明游戏内 Boss 红点、阶段脚本和最终奖励已完成。原创仓库不参与更新。

## 安装与回退

关闭两款游戏后，在本项目目录运行 PowerShell 7：

```powershell
& .\scripts\update-installed.ps1 -Diagnostic
```

该命令校验安装文件及发行包哈希，备份上一版 DLL、JAR、配置、记录和只狼存档，再同时替换两端。保留 MC options.txt、只狼原始模组配置及最初恢复备份。任一步失败会回退两端与诊断配置。诊断只打开 combat_trace、native_hits 和有限的 GUI 点击记录，native_phase_finish 保持 0。正常更新不带 Diagnostic 会关闭这些诊断选项。

## 第一轮：只狼原生动作样本

1. 先只启动只狼，不开启 MC 桥接。进入场景，静止两秒，走动并普通攻击几次。
2. 对普通敌人完成一次红点忍杀，动作结束后静止两秒再移动。
3. 对一个 Boss 完成一次阶段忍杀，削掉一颗红点即可。记录 Boss 名称和阶段；动画结束后静止两秒。
4. 正常退出只狼到桌面，报告完成结果。读取动画链有效性、动作末尾 ID、阶段和原生伤害记录后，再确定 MC 交接与阶段调用。

这一轮采集自然发生的动作，不运行远程自动结束阶段的候选调用。

## 第二轮：双端验收

先等待第一轮日志核对及必要的修订，再启动 MC 专用单人世界并执行 `/sekirobridge on`。

- 背包：E 打开；单击拿起、单击放下、右键拆分、Shift 转移和真实拖动各做一次。切换窗口尺寸或 GUI 缩放后重复；黑边点击不能落到边缘格。若失败，记录模式、格子和操作。
- 只狼菜单：MC 背包关闭时 Esc 打开只狼菜单，尝试鼠标选择设置和返回。关闭菜单后 F6 返回 MC。其它只狼界面可以先 F6 交还输入，再操作；不保证全部脚本界面自动识别。菜单期间 MC 世界暂停，战斗命令不投递。
- 忍杀交接：对有红点的普通敌人按一次 R。记录是否启动动作、何时能重新走动、是否露出狼模型；随后重复一次 Boss 阶段忍杀。按住 R 不应重启等待计时。
- 普通受击：近战与箭各命中普通敌人一次，核对格挡、受击、HP/姿态及代理是否一致。伤害采用普通 Kusabimaru 原生 profile，尚无每种 MC 武器对应的原生击退/弹反 profile。

远程阶段结束另做一次受控验收，只有确认原生入口、免疫/剧情条件和阶段脚本后才启用候选。须逐项核对红点减少、下一阶段正常启动、最终死亡与奖励，以及上一阶段飞行中的投射物不会重复削红点。

## 记录

只狼记录在 data_root 下的 combat-trace-*.jsonl，动画 kind="animation-state"；MC 的 logs/latest.log 中 GUI click 记录显示界面尺寸、指针和实际 slot，GUI server after-click 显示延迟的服务端 revision/cursorCount。诊断有时长/数量上限；完整的游戏内鼠标路径仍需要实际验收。
