# MC 主导人物与相机：mc-owner1

这是配套的只狼 DLL + MC JAR/JNI 更新。两款游戏正常退出后一起替换。原创仓库及存档保持独立。本版没有由助手启动游戏做实机测试。

## 操作方式

在专用 Minecraft 单人创造世界输入 `/sekirobridge on`，切回只狼可活动场景。默认第一人称；启用桥接后按 MC 的键位操作。

| 操作 | 默认按键 |
| --- | --- |
| 移动 / 跳跃 | WASD / Space |
| 潜行 / 疾跑 | Shift / Ctrl |
| 创造飞行 | 双击 Space；Space 上升，Shift 下降 |
| 背包 / 丢弃 / 换手 | E / Q / F |
| 第一人称与两个第三人称 | F5 |
| 挖掘、攻击 MC 生物 / 放置、使用 | 左键 / 右键 |
| 选物品 | 1–9 / 滚轮 |
| 桥接诊断 / 暂停 MC 输入 / 起始草方块 | F7 / F8 / F9 |

I/O/J、Alt 潜行和 F6 飞行已由 MC 默认逻辑替代。F7/F8/F9 保留给桥接。F8 仅暂停 MC 输入；恢复只狼操作请在 MC 执行 `/sekirobridge off`，或关闭 F7 中的 MC player / camera adapter。

MC 自己计算人物位置、速度、重力、跳跃、飞行、走跑动画与方块碰撞；单人服务器只在建立连接时传送一次。原生位置钩子将结果同步给隐藏的只狼角色。相机来自 MC 的实际渲染相机，写入当前只狼 ChrCam 更新结果；MC 的 F5 同时改变两端视图。

MC 的视野设置、疾跑及望远镜缩放继续计算，实际世界视野随帧传递。桥接期间暂时关闭走路摇晃和受伤镜头倾斜，避免这些额外变换与两端相机元数据不一致。

## 必须在游戏内验收的项目

1. **背包**：E 打开；快速单击拿起和放下物品、右键分堆、拖动、Shift 点击转移、创造搜索。按钮按下/松开及各自位置应保留，显示的光标应对准实际槽位。不同窗口大小和 Windows 缩放下再检查一次。
2. **只剩一套动作**：WASD、跳跃、疾跑、潜行，观察 MC 身体与四肢动画。E 不触发只狼钩锁，鼠标不触发只狼战斗。打开背包时人物应停下；关掉后恢复移动。
3. **视角与重影**：慢转、快速转头、直视上方/下方，F5 三种视角。方块应留在世界位置；不能有旧帧回跳。离线通过仅证明帧顺序与矩阵计算，不代替实际游戏渲染时序验收。
4. **MC 方块**：F9 生成起始方块，右键在邻面放置；走向墙、跳上方块、半砖、楼梯和天花板。交互射线、碰撞与创造飞行均采用 MC 原逻辑。
5. **原生地面**：在平地、斜坡、小台阶及悬崖边行走/跳跃/飞行落地。F7 的 MC positions 与 MC camera 计数应增加。原生地面是实验高度场；异常时关闭 adapter，记录当时场景和动作。
6. **释放与重连**：关闭桥接、离开 MC 世界、只狼读图、死亡、切换窗口、调整大小。原角色和输入应恢复；新场景重新从原生位置建立连接，而不是从旧 MC 出生点继续。

## 原生接口和边界

仅支持已校验的本机只狼 1.06。位置写入点、相机尾部和射线函数均检查运行时代码签名。当前 ChrCam 指针还必须与 FieldArea 的相机匹配。未匹配时 MC 控制保持等待，不能退回猜测写地址。

原生射线在玩家物理线程取得附近 9×9 个地面高度，临时加入 MC 本玩家碰撞查询；不在 MC 存档生成屏障。只表示局部地面，尚不完整支持原生垂直墙面、屋顶、悬檐、动态物体及复杂楼层。MC 生物不共享该地面，只狼 NPC 也不会碰撞 MC 方块。跨游戏伤害和战斗尚未接入。

原生接口和真实游戏效果仍需验收，尤其是射线、落地、相机更新时序与快速转头。日志新增 `MC driver cameraCalls`、`controlledMoves`；读取次数不等于功能已经验收。

发布前检查包括：真实 x64 位置/相机 detour 的寄存器恢复、GUI 客户区坐标、完整短点击的跨进程传输、JNI 边界校验、MC 相机/地面包布局、D3D11 遮挡和垂直视角合成、开发及发行 Mixin 目标检查。所有夹具均不运行两款游戏。
